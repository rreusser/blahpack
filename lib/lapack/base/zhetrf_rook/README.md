# zhetrf_rook

> Compute the bounded Bunch-Kaufman (rook) factorization of a complex Hermitian indefinite matrix (blocked algorithm).

<section class="intro">

`zhetrfRook` factors

```text
A = U*D*(U^H)   or   A = L*D*(L^H)
```

where `U` (or `L`) is a product of permutation and unit upper (lower) triangular matrices, and `D` is Hermitian and block diagonal with 1x1 and 2x2 blocks. Pivot selection uses the bounded Bunch-Kaufman ("rook") strategy, which performs an additional row/column search at each step compared to standard partial pivoting and produces stronger backward error bounds.

</section>

<!-- /.intro -->

<section class="usage">

## Usage

```javascript
var zhetrfRook = require( '@stdlib/lapack/base/zhetrf_rook' );
```

#### zhetrfRook( order, uplo, N, A, LDA, IPIV, strideIPIV )

Computes the bounded Bunch-Kaufman (rook) factorization of a complex Hermitian indefinite matrix.

```javascript
var Complex128Array = require( '@stdlib/array/complex128' );
var Int32Array = require( '@stdlib/array/int32' );

var A = new Complex128Array( [ 4, 0, 1, -2, 1, 2, 5, 0 ] );
var IPIV = new Int32Array( 2 );

zhetrfRook( 'column-major', 'lower', 2, A, 2, IPIV, 1 );
```

The function has the following parameters:

-   **order**: storage layout (`'row-major'` or `'column-major'`).
-   **uplo**: which triangle of `A` is referenced (`'upper'` or `'lower'`).
-   **N**: order of the matrix `A`.
-   **A**: input/output Hermitian matrix ([`Complex128Array`][@stdlib/array/complex128]). On exit, contains the factorization. Diagonal entries are forced to be real.
-   **LDA**: leading dimension of `A`.
-   **IPIV**: output pivot index array ([`Int32Array`][mdn-int32array]) of length `N`. Entries are 0-based; for a 2x2 pivot block, BOTH entries are negative and each encodes its own swap target via bitwise NOT (`~IPIV[k]`).
-   **strideIPIV**: stride for `IPIV`.

The function returns an `info` integer: `0` on success, `k > 0` (1-based) if `D(k,k)` is exactly zero (the factorization completes but `D` is singular).

#### zhetrfRook.ndarray( uplo, N, A, strideA1, strideA2, offsetA, IPIV, strideIPIV, offsetIPIV )

Same operation, with full ndarray (stride/offset) semantics for every array argument.

```javascript
var Complex128Array = require( '@stdlib/array/complex128' );
var Int32Array = require( '@stdlib/array/int32' );

var A = new Complex128Array( [ 4, 0, 1, -2, 1, 2, 5, 0 ] );
var IPIV = new Int32Array( 2 );

zhetrfRook.ndarray( 'lower', 2, A, 1, 2, 0, IPIV, 1, 0 );
```

The additional parameters relative to the BLAS-style API are:

-   **strideA1**: stride along the first dimension of `A` (in complex elements).
-   **strideA2**: stride along the second dimension of `A` (in complex elements).
-   **offsetA**: starting complex-element index for `A`.
-   **offsetIPIV**: starting index for `IPIV`.

</section>

<section class="notes">

## Notes

-   The implementation is a blocked driver: it calls `zlahef_rook` for full panels of width `NB` (64, from `ilaenv`) and falls back to the unblocked kernel `zhetf2_rook` for the trailing submatrix.
-   `IPIV` follows the stdlib bitwise-NOT convention: positive entries indicate a 1x1 pivot whose target row is the value itself; negative entries `~p` indicate a 2x2 pivot block whose swap target is `~IPIV[i]`. Because rook pivoting performs an extra row/column search, the two entries of a 2x2 block can encode different swap targets (unlike the original Bunch-Kaufman variant).
-   For Hermitian matrices, the diagonal entries of `A` are real-valued; the imaginary parts on the diagonal are forced to zero on exit.

</section>

## Examples

```javascript
var Complex128Array = require( '@stdlib/array/complex128' );
var Int32Array = require( '@stdlib/array/int32' );
var zhetrfRook = require( '@stdlib/lapack/base/zhetrf_rook' );

var A = new Complex128Array( [
    4, 0, 1, -2, 3, 1, 0.5, -0.5,
    0, 0, 5, 0, 2, -1, 1, 2,
    0, 0, 0, 0, 7, 0, 3, 0,
    0, 0, 0, 0, 0, 0, 6, 0
] );
var IPIV = new Int32Array( 4 );

var info = zhetrfRook( 'column-major', 'lower', 4, A, 4, IPIV, 1 );
console.log( info );
console.log( IPIV );
```

## Reference documentation

From the reference LAPACK 3.12.0 source of `ZHETRF_ROOK`, converted to Markdown with KaTeX math. Indices are the 1-based Fortran indices of the source.

> Computes the factorization of a complex Hermitian indefinite matrix using the bounded Bunch-Kaufman ("rook") diagonal pivoting method (blocked algorithm, calling Level 3 BLAS).

### Purpose

ZHETRF\_ROOK computes the factorization of a complex Hermitian matrix A using the bounded Bunch-Kaufman ("rook") diagonal pivoting method. The form of the factorization is

$$
A = U \, D \, U^T \quad\text{or}\quad A = L \, D \, L^T
$$

where U (or L) is a product of permutation and unit upper (lower) triangular matrices, and D is Hermitian and block diagonal with 1-by-1 and 2-by-2 diagonal blocks.

This is the blocked version of the algorithm, calling Level 3 BLAS.

### Arguments

#### UPLO `[in]`

_CHARACTER\*1_

-   `= 'U'`: Upper triangle of A is stored;
-   `= 'L'`: Lower triangle of A is stored.

#### N `[in]`

_INTEGER_

The order of the matrix A. $N \ge 0$.

#### A `[in,out]`

_COMPLEX\*16 array, dimension (LDA,N)_

On entry, the Hermitian matrix A. If `UPLO = 'U'`, the leading N-by-N upper triangular part of A contains the upper triangular part of the matrix A, and the strictly lower triangular part of A is not referenced. If `UPLO = 'L'`, the leading N-by-N lower triangular part of A contains the lower triangular part of the matrix A, and the strictly upper triangular part of A is not referenced.

On exit, the block diagonal matrix D and the multipliers used to obtain the factor U or L (see below for further details).

#### LDA `[in]`

_INTEGER_

The leading dimension of the array A. $\mathrm{LDA} \ge \max (1,N)$.

#### IPIV `[out]`

_INTEGER array, dimension (N)_

Details of the interchanges and the block structure of D.

If `UPLO = 'U'`:

Only the last KB elements of `IPIV` are set.

If $\mathrm{IPIV}(k) > 0$, then rows and columns k and `IPIV(k)` were interchanged and D(k,k) is a 1-by-1 diagonal block.

If $\mathrm{IPIV}(k) < 0$ and $\mathrm{IPIV}(k-1) < 0$, then rows and columns k and -`IPIV(k)` were interchanged and rows and columns k-1 and -`IPIV(k-1)` were inerchaged, D(k-1:k,k-1:k) is a 2-by-2 diagonal block.

If `UPLO = 'L'`:

Only the first KB elements of `IPIV` are set.

If $\mathrm{IPIV}(k) > 0$, then rows and columns k and `IPIV(k)` were interchanged and D(k,k) is a 1-by-1 diagonal block.

If $\mathrm{IPIV}(k) < 0$ and $\mathrm{IPIV}(k+1) < 0$, then rows and columns k and -`IPIV(k)` were interchanged and rows and columns k+1 and -`IPIV(k+1)` were inerchaged, D(k:k+1,k:k+1) is a 2-by-2 diagonal block.

#### WORK `[out]`

_COMPLEX\*16 array, dimension (MAX(1,LWORK))_

On exit, if `INFO = 0`, `WORK(1)` returns the optimal `LWORK`.

#### LWORK `[in]`

_INTEGER_

The length of `WORK`. $\mathrm{LWORK} \ge 1$. For best performance $\mathrm{LWORK} \ge N \, \mathrm{NB}$, where NB is the block size returned by ILAENV.

If `LWORK = -1`, then a workspace query is assumed; the routine only calculates the optimal size of the `WORK` array, returns this value as the first entry of the `WORK` array, and no error message related to `LWORK` is issued by XERBLA.

#### INFO `[out]`

_INTEGER_

-   `= 0`: successful exit
-   `< 0`: if `INFO = -i`, the i-th argument had an illegal value
-   `> 0`: if `INFO = i`, D(i,i) is exactly zero.  The factorization has been completed, but the block diagonal matrix D is exactly singular, and division by zero will occur if it is used to solve a system of equations.

### Further Details

If `UPLO = 'U'`, then $A = U \, D \, U^T$, where

$$
U = P(n) \, U(n) \, \cdots \, P(k)U(k) \, \cdots
$$

i.e., U is a product of terms $P(k) \, U(k)$, where k decreases from n to 1 in steps of 1 or 2, and D is a block diagonal matrix with 1-by-1 and 2-by-2 diagonal blocks D(k). P(k) is a permutation matrix as defined by `IPIV(k)`, and U(k) is a unit upper triangular matrix, such that if the diagonal block D(k) is of order s ($s = 1$ or 2), then

```text
        (   I    v    0   )   k-s
U(k) =  (   0    I    0   )   s
        (   0    0    I   )   n-k
           k-s   s   n-k
```

If $s = 1$, D(k) overwrites `A(k,k)`, and v overwrites `A(1:k-1,k)`. If $s = 2$, the upper triangle of D(k) overwrites `A(k-1,k-1)`, `A(k-1,k)`, and `A(k,k)`, and v overwrites `A(1:k-2,k-1:k)`.

If `UPLO = 'L'`, then $A = L \, D \, L^T$, where

$$
L = P(1) \, L(1) \, \cdots \, P(k) \, L(k) \, \cdots
$$

i.e., L is a product of terms $P(k) \, L(k)$, where k increases from 1 to n in steps of 1 or 2, and D is a block diagonal matrix with 1-by-1 and 2-by-2 diagonal blocks D(k). P(k) is a permutation matrix as defined by `IPIV(k)`, and L(k) is a unit lower triangular matrix, such that if the diagonal block D(k) is of order s ($s = 1$ or 2), then

```text
        (   I    0     0   )  k-1
L(k) =  (   0    I     0   )  s
        (   0    v     I   )  n-k-s+1
           k-1   s  n-k-s+1
```

If $s = 1$, D(k) overwrites `A(k,k)`, and v overwrites `A(k+1:n,k)`. If $s = 2$, the lower triangle of D(k) overwrites `A(k,k)`, `A(k+1,k)`, and `A(k+1,k+1)`, and v overwrites `A(k+2:n,k:k+1)`.
